# 0007: Embeddable badge

Status: accepted

## Context

Other sites (a shop, a profile page, a forum signature) want to show that a Nostr key and a BCH address belong together. A
static image would only repeat what this site claims. The badge has to check the binding itself, and it has to be framed by
pages on other origins, while the rest of the site keeps refusing to be framed (ADR 0004).

## Decision

- `/embed/<npub, hex key or address>` serves a small page built by Vite as a second entry (`web/embed.html`,
  `web/embed/main.ts`). It does not load React or the app bundle; it imports `src/core/badge.ts`, which calls the same
  `lookupInput` and `verifyBinding` as Look up. Nothing is copied.
- States: verified (newest binding passes every step and still claims the address that was asked for), no verified link,
  relays unreachable, bad input. "Unreachable" is decided by a separate probe (`src/core/probe.ts`: a REQ with `limit: 0`
  to each relay, counting the relays that answer), run in parallel with the look-up, so a relay outage is never shown as
  "not linked". A tampered or revoked binding is never shown as verified.
- `/embed.js` is generated by the server from config (frame size, titles in both languages): for each
  `<script data-tambat-id>` it inserts one iframe pointing at the origin the script came from. Plain ES5, no globals.
- Headers: `/embed/<id>` gets the server policy with `frame-ancestors` replaced by `embed.frameAncestors` (default `*`);
  every other path, including `/embed/` with no id and the built `web/embed.html`, keeps `frame-ancestors 'none'`. The
  config parser refuses `'none'` and any source containing a space, comma or semicolon.
- Text: `embed.*` keys in `lang/en.json` and `lang/ms.json`; `?lang=` picks the language.

## Consequences

- A host page trusts this site for the badge code, not for the result, which comes from relays and is verified in the
  browser. Sites that want no dependency can run the CLI or the one-file verifier.
- Each badge opens one extra connection per relay for the probe.

## Rollback

Remove the `embed` input from `vite.config.ts` and `registerEmbed` from `server/app.ts`; `/embed/*` then falls back to the
app under `frame-ancestors 'none'`.
